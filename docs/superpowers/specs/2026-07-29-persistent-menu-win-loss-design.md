# 常驻菜单与赢输按钮设计

## 背景

当前预览页面菜单需要通过顶部把手或下拉手势显示，操作不够直接；本局胜负按钮使用“地主赢 / 地主输”，文字偏小，两个模式的视觉区别不足。

## 目标

- 顶部六项预览菜单始终可见，不再使用把手、下拉手势或滚动自动隐藏。
- 在宽度 360 像素的手机上，六项菜单同排、一次显示齐全。
- 胜负按钮只显示“赢 / 输”，字体更大，并通过不同选中色明显区分两种状态。
- 保持对局中首页核心记分流程在 360×800 及以上竖屏中一屏可见。
- 不改变计分规则、会话数据、本地存储、撤回、PWA 离线及更新行为。

## 顶部菜单

- 删除预览菜单把手及其屏幕阅读器文本。
- 删除菜单打开状态、顶部下拉阈值、触摸监听和滚动自动关闭逻辑。
- 菜单恢复为正常文档流中的常驻区域，不使用固定定位或覆盖层。
- 菜单保持六个现有目的地和活动项状态，显示文字改为：
  - 首页（空）→ 空桌
  - 首页（对局中）→ 对局
  - 新建场次 → 新建
  - 历史场次 → 历史
  - 场次详情 → 详情
  - 设置 → 设置
- 使用六等分单行网格；宽度 360 像素时无横向滚动、无换行。
- 每个菜单按钮高度接近 44 像素，文字保持清晰。

## 赢输按钮

- `#landlord-win` 显示“赢”，`#landlord-loss` 显示“输”。
- 两个按钮保持等宽、单行排列，最小高度不低于 48 像素。
- 字号约 22–24 像素，加粗显示。
- 未选中时保持现有深色底和浅色文字。
- “赢”选中时使用红色底、金色或白色文字。
- “输”选中时使用蓝绿色底、白色文字。
- 继续通过现有 `selected` 状态控制逻辑选择胜负，不改变业务数据中的布尔值。

## 响应式与可访问性

- 360×800、390×844、430×932 为验收视口。
- 六项菜单在三种视口中均同排完整显示。
- 活动菜单项继续提供明显的背景与边框状态。
- 赢输按钮的文字、颜色和选中状态共同表达模式，不只依赖颜色。
- 键盘焦点、按钮语义和禁用逻辑保持可用。
- 保留 iPhone 顶部安全区避让，但菜单不覆盖应用内容。

## 测试与验收

测试先行：

1. 添加失败测试，要求把手和下拉菜单状态逻辑不存在，六项简写菜单仍能切换页面。
2. 添加失败测试，要求胜负按钮文本为“赢 / 输”，并具有独立的选中样式类。
3. 实现最小 HTML、CSS、JavaScript 调整后运行完整交互和 PWA 测试。
4. 在 360×800、390×844、430×932 浏览器视口验证：
   - 六项菜单单排且无横向溢出；
   - 赢输按钮放大并可明显区分选中状态；
   - 确认记分按钮无需滚动即可看见；
   - 记分、撤回和最近三局折叠仍正常。
5. 因 `preview.html` 属于预缓存外壳，发布时将 Service Worker 缓存版本从 `v3` 递增到 `v4`。

## 验收标准

- 页面打开后菜单立即可见，不需要任何额外手势。
- 360 像素宽度下六项菜单同时可见、无换行、无横向滚动。
- 胜负区只显示大号“赢 / 输”，两种选中状态颜色明显不同。
- 360×800 下核心记分流程仍完整位于一屏内。
- 所有自动化测试通过，线上发布后已安装 PWA 可通过显式更新切换到 `v4`。
