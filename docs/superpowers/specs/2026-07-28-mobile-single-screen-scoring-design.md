# 斗地主记分移动端单屏布局设计

## 背景

当前“对局中首页”在常见手机视口中需要多次向下滚动，才能完成一局记分。主要高度由预览页面菜单、三条最近对局、分散排列的表单标题、炸弹计数器以及结果预览框占用。

本次调整只优化界面布局与显示方式，不改变记分规则、数据结构、本地存储、撤回逻辑、PWA 离线能力和其他页面的业务行为。

## 目标

- 在宽度 360 像素、高度 800 像素及以上的竖屏手机中，无需页面滚动即可看到并操作对局中首页的核心记分流程。
- 保留总分、创建场次、撤回上一局、结束场次、地主、胜负、踢/反踢、炸弹数和确认记分。
- 保持现有暗色、金色、红色视觉风格及玩家识别色。
- 触控按钮继续保持清晰、易点，不以显著缩小点击区域换取空间。

## 已确认的布局方案

采用“紧凑单屏”方案。

### 预览页面菜单

- “首页（空）”到“设置”的预览菜单默认收起，不占用正常记分区域高度。
- 用户在页面顶部向下拉，或页面向上滚动回顶部时，菜单从顶部滑出。
- 菜单显示后，用户向下浏览或点击菜单项时自动收起。
- 提供一条很窄但可识别的顶部把手，保证鼠标、键盘和不支持下拉手势的环境仍能打开菜单。
- 菜单保持原有页面切换能力及活动项标识。

### 对局概览

- 应用标题栏保留。
- 三个玩家总分卡保持一行，减少上下内边距，但不降低姓名和分数的视觉层级。
- “新建场次”“撤回上一局”“结束场次”继续保持同一行。

### 最近三局

- 默认折叠为一条紧凑摘要行，显示“最近三局”、最新一局摘要和展开状态。
- 点击摘要行展开现有三条记录；再次点击收起。
- 展开内容覆盖在正常流程中或临时增加页面高度，不要求展开后仍维持单屏。
- 完成记分或重新渲染时默认回到折叠状态，避免持续挤占核心操作区。

### 本局记分

- 地主选择保持三列，并继续使用玩家颜色圆点和强调条。
- 胜负保持两列。
- 踢/反踢区域只在已选择地主后显示对应两位农民的独立状态按钮。
- “炸弹数”和减号、当前数值、加号放在同一行。
- 删除常驻的“请选择地主和胜负”及算分预览框。
- 规则错误仍通过精简反馈区域显示；无错误时该区域不占高度。
- “确认记分”保持全宽主按钮；条件不足时仍为禁用状态。

## 响应式行为

- 设计基准为 360×800、390×844 和 430×932 三组竖屏视口。
- 360×800 下优先保证所有核心控件可见，允许浏览器地址栏、安全区和字体渲染产生少量差异。
- 高度小于 800 像素或用户启用大号系统字体时，页面允许正常滚动，不遮挡或裁切操作。
- 宽屏预览仍限制在现有手机容器宽度内，不改变桌面端展示方式。
- 使用 `env(safe-area-inset-*)` 避让 iPhone 刘海和底部手势区。

## 可访问性与交互

- 折叠按钮通过 `aria-expanded` 和 `aria-controls` 表达状态。
- 顶部菜单把手具有明确的可访问名称，并支持 Enter/Space。
- 隐藏区域不保留可聚焦的不可见控件。
- 动效尊重 `prefers-reduced-motion`，关闭动画时立即切换状态。
- 主要触控目标维持接近 44×44 像素；圆形炸弹按钮不缩小。

## 测试策略

测试先行，先添加失败测试，再调整结构与样式：

1. DOM 测试确认结果预览框已移除，错误反馈及确认按钮仍存在。
2. DOM 测试确认炸弹标题与计数器位于同一行。
3. DOM 测试确认最近三局默认折叠、可展开、可再次收起，并正确维护 `aria-expanded`。
4. DOM 测试确认预览菜单默认收起，可通过把手和顶部下拉手势显示。
5. 现有记分、撤回、独立踢/反踢、PWA 注册和离线测试全部继续通过。
6. 在 360×800、390×844 和 430×932 视口进行浏览器验证，确认核心记分控件一屏可见。
7. 在已安装 PWA 的 standalone 模式验证安全区、离线启动和触控交互。

## 验收标准

- 常见 360×800 及以上竖屏手机首次进入“对局中首页”时，核心记分流程无需页面滚动。
- 顶部预览菜单默认不占布局高度，能够下拉或通过把手打开。
- 最近三局默认只占一行，并能完整展开和收起。
- 页面不再显示结果预览框。
- 炸弹数标题和计数器同排显示。
- 原有记分结果和撤回结果不发生变化。
- 自动化测试全部通过，三组目标视口的浏览器验证无横向溢出、遮挡或不可点击控件。
